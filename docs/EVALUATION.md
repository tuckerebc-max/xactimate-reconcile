# Evaluation and maintenance

Run the new test suite, the separately retained C suite and all three worked cases. Validate extension packs and inspect generated documents. Read the release validation report for the exact checks actually performed.

Before real-claim deployment, evaluate a deidentified set of company cases held out from prompt and exemplar development. Include shingle, tile and low-slope roofs, native PDFs, scans, phone images, multiple estimate versions, repairable damage and a claim where the carrier's estimate is correct.

| Measure | Evidence to retain |
|---|---|
| Numeric extraction | Page/crop oracle, digit/unit error counts and material dollar effects |
| Line mapping | Estimator adjudication of one-to-one, bundle and unmatched operations |
| Arithmetic | Independent totals, reductions, rounding and financial bases |
| Evidence quality | Every material proposition linked to a source; unsupported statements held |
| Advocacy quality | Fair counterargument, accurate request, no fabricated entitlement |
| Software handoff | Licensed operator reproduces the revision and reconciles its export |
| Role and approval | Actual source reviewers and sender authority; truthful review descriptions |

Do not use uplift in claim dollars as the main quality score. A high-quality result may reduce a proposed charge, accept the carrier's position or request more evidence. Record both false additions and missed supported items.

Maintenance sequence: add a source or approved exemplar; version its pack; run regression tests and held-out cases; inspect changed output; document the observed benefit and new limits. Update applicable laws, code adoptions, quotes and software workflow references as evidence changes. Keep price evidence dated and geographically bounded.
