## Conflict resolution

The assignment explicitly asks for research/build handoff and prohibits unfinished skill installation. That scope takes precedence over Writing Skills' automatic deployment checklist and Skill Creator's save/install workflow. We harvested those methods without installing or modifying a skill. The architecture is a contract for a future skill, not a SKILL.md disguised under another name.

The writing constitution permits expressive openings and rhetorical devices; a formal estimating letter needs a direct request and traceable amounts. Prose Craft's curiosity-first opener therefore gives way to the assignment's exact factual request. Its common-mistakes row says intentional devices can be exempt from caps, while its main rules call the caps absolute; the stricter main rule controls, though this deliverable needs no ornamental devices.

Prose Craft excludes code and structured data. It governs the memo and letter only. Audit and calculator messages prioritize unambiguous instructions. The source audit's folder-name rule has an environment-specific exception: installed personal-skill folders have reconciled IDs, so their IDs are not treated as a defect or renamed.

Public platform docs and this environment can have different installation routes. Current environment instructions control local skill operations; the portable core contains neither those paths nor host tool names. Claude's cross-surface documentation conflict is recorded in adapters/PORTABILITY.md and C_SOURCES.json.

A favorable source rule, manufacturer instruction or Arizona argument is research evidence. It does not become an obligatory estimate line or a coverage determination. A/B returns remain integration dependencies.
